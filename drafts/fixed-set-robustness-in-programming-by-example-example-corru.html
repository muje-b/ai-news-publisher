Fixed-Set Robustness in Programming by Example: Example Corruption and Semantic Partition Recovery

Programming‑by‑example (PBE) tools aim to infer a program that matches a handful of input‑output pairs. Most research assumes that noisy examples arise from random mistakes, so the synthesizer can tolerate them by minimizing an expected loss. The paper “Fixed‑Set Robustness in Programming by Example: Example Corruption and Semantic Partition Recovery” flips this assumption: it asks what happens when an adversary, who knows the synthesizer’s algorithm, deliberately selects which examples to corrupt in order to cause the greatest possible damage to the returned program. By studying this worst‑case corruption model, the authors expose a limitation of existing PBE systems and propose a concrete defense.

What You Need to Know

The authors focus on finite version spaces—the set of all programs consistent with a given DSL and a bounded pool of candidate examples. They define fixed‑set worst‑case corruption as the maximum degradation in synthesis quality when an adversary may corrupt up to k examples from that pool, choosing the subset that hurts the synthesizer the most. This formulation is deterministic; there is no probability distribution over noise, only a combinatorial search for the most damaging set of corruptions.

To make the problem tractable, they implement two complementary search strategies for a string‑transformation DSL. The first is an exact‑within‑bounded‑pool algorithm that enumerates all subsets of size ≤ k and evaluates the resulting synthesizer output, guaranteeing the true worst case when the pool is small enough. The second is a heuristic that greedily picks examples likely to affect the version‑space partition, scaling to larger pools while still providing strong empirical bounds on the corruption impact.

As a defense, the paper introduces version‑space partition aggregation (VPA). The idea is to split the example set into disjoint groups, synthesize a candidate program from each group independently, and then combine the candidates by voting on their semantic signatures—compact descriptors of program behavior (e.g., output patterns on a validation set). If the adversary corrupts examples only within some groups, the uncorrupted groups still produce correct signatures, allowing the vote to outweigh the malicious influence.

Why It Matters

Current PBE systems are deployed in scenarios where users may inadvertently provide wrong examples, but they are also vulnerable to intentional manipulation—think of a malicious user trying to steer a code‑generation assistant toward a harmful or useless program. By formalizing adversarial corruption, the work highlights a gap between the typical stochastic noise model and realistic threat models, urging practitioners to consider robustness beyond average‑case performance.

The proposed VPA mechanism offers a practical mitigation that does not require retraining or altering the underlying synthesizer. It leverages the inherent structure of version spaces: partitioning reduces the influence any single corrupted example can have, while semantic voting aggregates evidence of correct behavior. This approach can be adapted to other DSLs and synthesis techniques, making the robustness insight broadly applicable.

Key Details

  • Fixed‑set worst‑case corruption assumes an adversary selects up to k examples from a known pool to maximize synthesis error.
  • The exact search enumerates all ≤ k subsets; feasible when the candidate pool is ≤ 30 examples for the evaluated string‑transformation DSL.
  • The heuristic search ranks examples by their effect on version‑space boundaries and iteratively builds a corrupt set, scaling to pools of several hundred examples.
  • Version‑space partition aggregation divides the example pool into g disjoint groups, synthesizes a program per group, and aggregates via semantic signature voting.
  • Experiments show VPA reduces the success rate of adversarial corruption from over 70 % to below 15 % across varying k values, while only modestly increasing synthesis time.
  • The defense is orthogonal to the synthesizer; any PBE engine that can produce semantic signatures can adopt VPA without modification.

What's Next

Future work could extend the fixed‑set corruption model to infinite or continuously growing example pools, exploring how the bound k scales with pool size. Additionally, investigating alternative aggregation schemes—such as weighted voting based on confidence measures or learning‑based signature classifiers—might further improve resilience. Finally, applying the same adversarial lens to other program synthesis domains (e.g., table‑manipulation or API‑call generation) would test the generality of the version‑space partitioning insight.
