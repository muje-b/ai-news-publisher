HyperAgent: Planning and Acting over Tool-Schema Hypergraphs for Tool-Use LLM Agents

When language models need to act in the real world, they often reach for external tools—APIs, calculators, databases, or robotic interfaces. Most current approaches ask the model to guess which tools to call based on textual descriptions, a process that can be slow and error‑prone, especially when the task requires several steps or when the environment changes during execution. The paper “HyperAgent: Planning and Acting over Tool‑Schema Hypergraphs for Tool‑Use LLM Agents” proposes a different way: it builds an explicit graph that captures how tools relate to each other through their input and output data schemas, then uses that graph to guide planning and execution.

What You Need to Know

The authors model each tool as a hyperedge that connects one or more input‑schema nodes to one or more output‑schema nodes. A schema node represents a type of data (e.g., “image JPEG”, “temperature float”, “user ID”). By linking tools through shared schemas, the resulting structure is a directed Tool‑Schema Hypergraph. This graph makes explicit which tools can follow others based on compatible data types, eliminating the need for the model to infer compatibility from free‑form text alone.

HyperAgent operates in two phases. First, it runs a graph‑search algorithm on the hypergraph to find a sequence of hyperedges (tools) that transforms the initial input schemas into the desired output schemas. Second, it executes the selected tools, monitoring the actual data produced at each step. If the observed output deviates from the expected schema, the agent can replan using the updated graph state, allowing it to adapt to changes in the environment or unexpected tool behavior.

The approach is evaluated on several benchmark suites that involve multi‑step tool use, such as composing image‑processing APIs, querying databases, and controlling simulated robots. HyperAgent consistently achieves higher success rates and fewer tool calls compared with baseline agents that rely solely on language‑model reasoning for tool selection.

Why It Matters

Reliable tool use is a bottleneck for deploying LLM agents in settings where precision matters—healthcare, manufacturing, or scientific experimentation. By grounding the planning process in a formal schema graph, HyperAgent reduces the guesswork that leads to unnecessary or failing tool calls. This can translate into lower latency, lower cost (fewer API invocations), and higher trustworthiness of the agent’s actions.

Moreover, the hypergraph representation is lightweight to update. When a new tool is added or an existing tool’s interface changes, only the corresponding hyperedges need to be modified. The planner automatically incorporates the change without retraining the language model, making the system easier to maintain as tool ecosystems evolve.

Key Details

  • Tools are represented as hyperedges from input‑schema nodes to output‑schema nodes.
  • The directed Tool‑Schema Hypergraph encodes feasible data‑flow transitions between tools.
  • HyperAgent uses a shortest‑path‑like search over the hypergraph to propose tool sequences.
  • Execution includes runtime schema validation; mismatches trigger replanning.
  • Experiments show a 15‑30 % increase in success rate over LLM‑only baselines on multi‑step tasks.
  • The method scales linearly with the number of tools and schemas in the graph.

What's Next

Future work could explore hypergraph‑based learning to refine edge weights based on observed tool performance, or integrate hierarchical schemas to handle more complex data structures. Extending the framework to support concurrent tool execution and to handle partial observability would also bring HyperAgent closer to operating in fully autonomous, real‑world settings.
